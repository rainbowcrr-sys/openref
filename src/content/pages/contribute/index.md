OpenRef 是一份开放的技术参考手册，按主题分组、条目式写作。如果你写过某件具体的事、踩过某个具体的坑，欢迎把它写成一个条目投给我们。

## 我们收什么

符合这些条件的稿件优先通过：

- **讲清一件事**：一篇只解决一个问题，不写"XX 入门大全"
- **有可运行的代码**：示例能直接跑，不是伪代码
- **写清限制**：额度、版本、边界条件，越具体越好
- **原创**：自己实践过的结论，不是翻译或拼凑

不收这几类：

- 纯产品推广、软文、广告
- 没有实质内容的随笔、日记
- 未授权转载的他人作品
- 涉及侵权、违法、隐私泄露的内容

## 格式要求

符合站点现有条目的六段结构（可直接在 `.md` 文件里写）：

```
一句话定义：X 是……

## 适用场景
- 该用 / 不该用

## 最小示例
（可运行代码）

## 说明
（逐条解释）

## 限制
（额度、版本、边界）

## 下一步
（相关条目链接）
```

写作语气：主语是技术，不是"我"。写"KV 写入额度为每天 1000 次"，不写"我觉得 KV 挺好用的"。

</details>

## 投稿前需要准备

| 项目 | 说明 | 必填 |
|---|---|---|
| 主题分类 | 属于哪个大类/子类，如"云原生 / Cloudflare" | 是 |
| 标题 | 一句话说清解决什么问题 | 是 |
| 正文 | Markdown 格式，或直接提交 `.md` 文件 | 是 |
| 署名 | 笔名、真名或"匿名" | 是 |
| 参考链接 | 官方文档、出处 | 否 |

:::warn 提交方式
**本页面不提供在线表单。** 所有稿件必须通过邮件提交，以确保内容安全与版权可追溯。
:::

## 提交步骤

1. 打开你的邮箱，新建一封邮件
2. **收件人**填：`submit@openref.de5.net`
3. **邮件主题**写：`[投稿] 你的文章标题`
4. **邮件正文**按下面模板填写：

```
主题分类：云原生 / Cloudflare
署名：你的名字（或"匿名"）
参考链接：（可选）

--- 正文开始 ---

一句话定义：R2 是……

## 适用场景
...
```

5. 如果正文较长，也可以**把 `.md` 文件作为附件**上传，正文里只写分类和署名
6. 发送

## 审核与通知

- 审核周期通常为 **1 至 7 个工作日**
- 通过后稿件会以你的署名发布，地址形如 `https://openref.de5.net/docs/.../`
- 你会收到一封来自 `no-reply@openref.de5.net` 的通知邮件，内含稿件链接

:::warn 该邮箱只发不收
通知邮件由 `no-reply@openref.de5.net` 发出，**请勿回复**，回复不会有任何回应。
:::

## 需要改动怎么办

稿件发布后如需修改、补充或撤稿，发邮件到 `submit@openref.de5.net`，主题写 `[修改] 原标题`，说明要改什么。
