# 07 · 邮箱体系（Cloudflare Email Routing 完整说明）

# ⭐ 今天要做的事（照这个清单做，约 15 分钟）

前提：`no-reply@openref.de5.net` 你已经建好并测试通过。

```
□ 1. 建 submit@     -> 收投稿              （必建）
□ 2. 建 contact@    -> 收读者来信/转载申请  （必建）
□ 3. 建 report@     -> 收内容勘误          （建议）
□ 4. 每条建完 -> 去 Gmail 点验证链接        <- 不点不生效！
□ 5. no-reply 改成 Drop（只发不收）
□ 6. Catch-all 关掉或改 Drop              <- 不关会被垃圾邮件灌满
□ 7. Gmail 里把 no-reply@ 设成发件别名（只做一次）
□ 8. 用另一个邮箱发一封到 submit@ 测试
```

⚠️ **全程注意**：DNS 里所有 MX / TXT（邮件）记录**永远保持灰云**。
橙云会让邮件直接失效。站点记录怎么改都行，邮件记录别碰。

# 第一部分：原理

## 一、邮件怎么流转

```
别人发到 xxx@openref.de5.net
      ↓
发件方的邮件服务器查 MX 记录
      ↓
找到 Cloudflare
      ↓
Cloudflare 查路由规则
      ↓
转发到你的 Gmail
      ↓
你在 Gmail 收到（发件人显示原始投稿人邮箱）
```

## 二、关键特性

| 特性 | 说明 |
|---|---|
| 费用 | **免费套餐就够** |
| 存储 | **Cloudflare 不存储邮件内容**，只转发 |
| 数量 | 一个域名可建多条地址（够用） |
| 延迟 | 通常几秒到几分钟 |

## 三、⚠️ 你收到的邮件发件人是谁

**是投稿人的原始邮箱**，不是 `submit@openref.de5.net`。

这是正常的。你想回信时，手动选 `no-reply@` 或 `contact@` 作为发件人即可。

# 第二部分：DNS 里的邮箱记录

## 一、有哪些

在 Cloudflare → `openref.de5.net` → **DNS → 记录**

| 类型 | 数量 | 作用 |
|---|---|---|
| **MX** | 3 条 | 告诉全世界"本域名的邮件交给 Cloudflare" |
| **TXT**（SPF） | 1 条 | 发件方策略，防伪造 |
| **TXT**（DKIM） | 1-2 条 | 邮件签名 |
| **TXT**（DMARC） | 1 条 | 收件方策略 |

## 二、⚠️ 铁律：永远灰云

**所有邮件相关记录必须保持灰色云朵（DNS only）。**

原因：**橙云是为网页流量设计的，不代理邮件。**
一旦开橙云，MX 记录会被 Cloudflare 的 IP 替换，邮件就收不到了。

## 三、这些记录是自动加的

开启 Email Routing 时，Cloudflare 会自动添加 MX 和 TXT。
**你不需要手动改，也别改。**

如果误删了：关闭 Email Routing 再重新开启，会自动重建。

# 第三部分：建立邮箱地址

## 一、开启 Email Routing（只做一次）

1. Cloudflare → 选 `openref.de5.net`
2. 左侧 **电子邮件** → **电子邮件路由**
3. 点 **启用电子邮件路由**
4. Cloudflare 说要添加 MX/TXT 记录 → 点 **添加记录并启用**
5. 状态变成"已启用"

## 二、建一个地址

1. **路由规则** 标签
2. 点 **创建地址**
3. 填写：

| 项 | 值 |
|---|---|
| 自定义地址 | 前缀，如 `submit` |
| 操作 | **发送到电子邮件** |
| 目标 | 你的 Gmail 地址 |

4. 点 **保存**
5. **⚠️ 去 Gmail 找验证邮件，点里面的链接确认**

**不确认就不会生效。** 验证邮件通常 1-5 分钟到。

## 三、你的邮箱清单

| 地址 | 用途 | 优先级 |
|---|---|---|
| `no-reply@openref.de5.net` | 只发通知，**设成 Drop** | ✅ 已有 |
| `submit@openref.de5.net` | 收投稿 | ✅ 必建 |
| `contact@openref.de5.net` | 收读者来信 + 转载申请 | ✅ 必建 |
| `report@openref.de5.net` | 收内容勘误 | ✅ 建议 |
| `business@openref.de5.net` | 商务合作 | 可选 |
| `security@openref.de5.net` | 安全反馈 | 可选 |
| `abuse@openref.de5.net` | 滥用举报 | 可选 |

这些地址都在 `/privacy/` 页面上列出来了，访客能看到。

# 第四部分：no-reply 特殊处理

## 一、问题

`no-reply` 语义是"别回我"，但**技术上照样能收信**。

别人发过来 → 按路由规则 → 转到你 Gmail → 你的收件箱变脏。

## 二、推荐方案：设成 Drop

1. 电子邮件路由 → **路由规则**
2. 找到 `no-reply` 那条 → 点 **编辑**
3. **操作** 改成 **Drop（丢弃）**
4. 保存

**效果**：

- 别人发过来 → **静默消失**
- 发件方不会收到退信（不知道被丢了）
- 你的 Gmail 干干净净
- 符合 `no-reply` 的本意

## 三、备选：保留但过滤

如果你想偶尔看看有没有重要误发：

1. 保留转发到 Gmail
2. Gmail 建过滤器：收件人包含 `no-reply@openref.de5.net` → 自动归档 + 加标签

# 第五部分：关掉 Catch-all

## 一、Catch-all 是什么

"捕获所有"：发给本域名**任何不存在地址**的邮件，都会转给你。

比如有人发 `abc@openref.de5.net`、`admin@openref.de5.net`、
`zhangsan@openref.de5.net` —— 全都会进你 Gmail。

## 二、风险

垃圾邮件发送者会**批量猜地址**，你的 Gmail 会被灌满垃圾。

## 三、怎么处理

1. 电子邮件路由 → **路由规则**
2. 找 **Catch-all** 那一条
3. 要么**删除**，要么改成 **Drop**

**推荐：改成 Drop 或删掉。**

# 第六部分：让 Gmail 能用 no-reply 发信

## 一、为什么需要

你回信通知投稿人时，希望对方看到发件人是
`no-reply@openref.de5.net`（官方地址），而不是你的个人 Gmail。

## 二、配置步骤

1. 登录 Gmail
2. 右上角齿轮 → **查看所有设置**
3. **账号和导入** 标签
4. 找到 **"用这个地址发送邮件"** → 点 **添加其他电子邮件地址**
5. 弹窗里：

| 项 | 值 |
|---|---|
| 名称 | `OpenRef` |
| 电子邮件地址 | `no-reply@openref.de5.net` |
| ☑ 视为别名 | **勾上** |

6. 点 **下一步** → **发送验证**
7. 去收件箱找验证邮件 → 点链接确认

## 三、之后怎么用

写新邮件时，**发件人**那一栏会出现下拉菜单，选 `no-reply@openref.de5.net`。

回复邮件时，点发件人地址也能切换。

## 四、SPF 对齐（可选但推荐）

为了让对方邮件服务器认这是合法发件，检查 DNS 里的 SPF 记录：

```
v=spf1 include:_spf.google.com ~all
```

如果 Cloudflare 自动生成的 SPF 里没有 `include:_spf.google.com`，手动加上。
（不加通常也能发，但可能进垃圾箱。）

# 第七部分：故障排查

| 现象 | 原因 | 解决 |
|---|---|---|
| **收不到邮件** | MX 记录被改成橙云 | 改回灰云 |
| **收不到邮件** | 目标 Gmail 没点验证链接 | 去 Gmail 找验证邮件 |
| **收不到邮件** | Email Routing 没启用 | 去 Cloudflare 启用 |
| **发的信进垃圾箱** | SPF/DKIM 没对齐 | 检查 TXT 记录 |
| **发信被退回** | 没配 Gmail 别名 | 按第六部分配 |
| **收到大量垃圾** | Catch-all 开着 | 关掉或改 Drop |
| **no-reply 收到信** | 没设 Drop | 按第四部分设 |

## 测试方法

给自己发一封：

1. 用另一个邮箱（或朋友的）
2. 发到 `submit@openref.de5.net`
3. 看 Gmail 有没有收到（**几分钟内**）

**这是最快的验证方式。**
