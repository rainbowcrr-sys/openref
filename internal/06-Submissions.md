# 06 · 投稿处理与转载申请（完整流程，一步不漏）

---

# 第一部分：投稿

## 一、投稿怎么到你手上

```
投稿人发邮件 → submit@openref.de5.net
      ↓ Cloudflare Email Routing 转发（MX 记录灰云）
你的 Gmail 收到
      ↓
你审核
      ↓
发布 + 用 no-reply@ 回信通知
```

⚠️ 你收到的邮件，**发件人显示的是投稿人原始邮箱**（不是 submit@），这是正常的。

## 二、投稿前必读：站点上写了什么

站点 `/contribute/` 页面告诉投稿人：

| 要求 | 内容 |
|---|---|
| 主题分类 | 属于哪个大类/子类 |
| 标题 | 一句话说清解决什么 |
| 正文 | Markdown 格式，或 `.md` 附件 |
| 署名 | 笔名/真名/匿名 |

邮件格式：

```
收件人：submit@openref.de5.net
主题：[投稿] 文章标题
正文：
  主题分类：云原生 / Cloudflare
  署名：张三
  参考链接：（可选）

  --- 正文开始 ---
  ...
```

---

## 三、审核：收不收

### ✅ 收

- 讲清一件事（一篇一个问题）
- 有能直接跑的代码
- 写清了限制（额度/版本/边界）
- 原创，实践过的结论

### ❌ 不收

- 纯广告、软文、推广
- 没有实质内容的随笔/日记
- 未授权转载
- 侵权、违法、泄露隐私

### ⚠️ 需修改后再审

- 代码跑不起来
- 缺"限制"段落
- 和站内已有条目重复
- 格式太乱

## 四、通过后的完整八步

### 第 1 步：定分类

按文章主题找 `src/content/docs/` 下对应大类/子类。
判断方法见 [04-Categories.md](04-Categories.md)。

分类不存在 → 先加（改 taxonomy.json + 建目录）。

### 第 2 步：建文件

```powershell
node scripts/new-post.mjs cloud/cloudflare/r2-storage "R2 对象存储入门"
```

### 第 3 步：整理成六段

按站点骨架整理：

```
一句话定义 → 适用场景 → 最小示例 → 说明 → 限制 → 下一步
```

**frontmatter 这样写**（保留投稿人信息）：

```yaml
---
title: R2 对象存储入门
description: 投稿人提供的摘要（或你改写）
pubDate: 2026-10-29
tags: [Cloudflare, R2]
---
```

**文末加一行署名**：

```markdown
---

本篇由 **张三** 投稿。查看[投稿人名录](/contribute/authors/)。
```

### 第 4 步：本地验证

```powershell
node build.mjs
```

确认没报错。

### 第 5 步：推送

```powershell
openref push "add: R2 对象存储入门（投稿）"
```

等 1-2 分钟，Actions 绿勾后上线。

### 第 6 步：确认线上地址

浏览器打开确认能访问，记下路径，例如：

```
https://openref.de5.net/docs/cloud/cloudflare/r2-storage/
```

### 第 7 步：回信通知

见第五部分。

### 第 8 步：更新投稿人名录

见第六部分。

## 五、回信模板（放在 `EMAIL-TEMPLATES.md`）

### 前置：配 Gmail 发件别名（只做一次）

1. Gmail → 齿轮 → **查看所有设置** → **账号和导入**
2. "用这个地址发送邮件" → **添加其他电子邮件地址**
3. 名称 `OpenRef`，地址 `no-reply@openref.de5.net`
4. 勾"视为别名" → **发送验证**
5. 收件箱点验证链接

之后写邮件时，发件人下拉能选 `no-reply@openref.de5.net`。

### 审核通过

**收件人**：投稿人邮箱
**发件人**：`no-reply@openref.de5.net`
**主题**：`【OpenRef】您的稿件已通过审核`
**正文**：

```
创作者您好！您的稿件已成功通过审核并上传。
https://openref.de5.net/docs/这里换成实际路径/

感谢您的投稿！ヾ(≧∇≦谢谢≧∇≦)ノ

请不要回复
```

### 需要修改

主题：`【OpenRef】您的稿件需要补充`

```
创作者您好！感谢投稿。

稿件在以下方面需要补充后再提交：

1. （具体问题，如：代码示例无法直接运行）
2. （如：缺少限制说明，请补充额度与版本要求）

修改后请再次发送至 submit@openref.de5.net，主题写 [修改] 原标题。

请不要回复
```

### 未通过

主题：`【OpenRef】关于您的投稿`

```
创作者您好！感谢投稿。

经审核，本次稿件暂未收录，原因是：

（例如：与现有条目重复 / 不在收录范围 / 技术结论无法验证）

欢迎参考投稿说明后再投其他主题：https://openref.de5.net/contribute/

请不要回复
```

### 存成 Gmail 模板（省事）

1. Gmail 设置 → **高级** → 启用 **模板** → 保存
2. 写新邮件，正文填上面模板
3. 右下角三点 → **模板** → **保存草稿为模板** → 取名 `审核通过`
4. 以后：新邮件 → 三点 → 模板 → 选它 → 改链接 → 发送

## 六、更新投稿人名录

编辑 `src/data/authors.json`，在 `authors` 数组加一条：

```json
{
  "name": "张三",
  "posts": [
    {
      "title": "R2 对象存储入门",
      "url": "/docs/cloud/cloudflare/r2-storage/",
      "date": "2026-10-29"
    }
  ]
}
```

推送后 `/contribute/authors/` 自动更新，**不用改 Markdown**。

⚠️ 投稿人明确说"不要列入名录"的，**别加**。

完整字段说明见 [05-Config-Files.md](05-Config-Files.md) 第四部分。

# 第二部分：转载申请

## 一、政策是什么

站点 `/legal/copyright/` 页面写明：

**允许转载，但三个条件缺一不可：**

1. **必须署名原作者**
2. **必须包含原文链接**（可点击）
3. **必须事先申请并获得同意**

申请邮箱：**`contact@openref.de5.net`**
审核周期：**3 个工作日内回复**

## 二、收到申请后的判断

### ✅ 同意

- 个人博客、技术论坛
- 非商业用途
- 不做实质性删改
- 会标注署名和原文链接

### ❌ 拒绝

- 商业用途（付费课程、收费专栏、商业出版）
- 整站镜像 / 批量抓取
- 计划对内容做实质性删改
- 不给署名或不放链接

### ⚠️ 需补充信息

- 没说清转载平台
- 没说是否商业用途
- 没说是否删改

## 三、回信模板

### 同意转载

**发件人**：`no-reply@openref.de5.net`
**主题**：`【OpenRef】转载申请已同意`

```
您好！您的转载申请已同意。

允许转载的条目：
https://openref.de5.net/docs/这里换成实际路径/

转载时请务必满足以下三条：
1. 清晰标注原作者署名：XXX
2. 在转载页面显著位置放置原文链接（可点击）：
   https://openref.de5.net/docs/这里换成实际路径/
3. 不对内容做实质性删改（如确需删改请再次邮件说明）

本同意仅针对上述条目，转载其他条目需另行申请。
内容许可：CC BY-NC-SA 4.0（署名 - 非商业性使用 - 相同方式共享）

请不要回复
```

### 拒绝转载

**主题**：`【OpenRef】关于您的转载申请`

```
您好！感谢来函。

本次转载申请未予同意，原因是：

（例如：涉及商业用途 / 申请范围为整站镜像 / 计划对内容做实质性删改）

如有疑问或调整后可再次申请，发至 contact@openref.de5.net。

请不要回复
```

### 需补充信息

**主题**：`【OpenRef】转载申请需补充信息`

```
您好！收到您的转载申请，还需补充以下信息才能审核：

1. 具体的转载平台名称与账号（如公众号名称）
2. 是否为商业用途
3. 是否会对内容做删改

补充后发至 contact@openref.de5.net，我们在 3 个工作日内回复。

请不要回复
```

## 四、⚠️ 3 个工作日承诺

站点上写了"3 个工作日内回复"，**尽量别拖过**。

如果确实忙，至少先回一封"已收到，正在审核"。

## 五、发现未授权转载怎么办

1. 先发邮件要求补上署名和原文链接，或删除
2. 保留截图证据
3. 如果对方不理，可在 Cloudflare 层面屏蔽其来源（高级操作，一般不用）

# 第三部分：其他来信

| 邮箱 | 收到什么 | 怎么处理 |
|---|---|---|
| `contact@openref.de5.net` | 读者交流、转载申请 | 按内容回复 |
| `report@openref.de5.net` | 内容勘误 | 核实后改文章，回复感谢 |
| `no-reply@openref.de5.net` | 别人误发 | **设成 Drop，收不到** |

## 勘误处理

1. 核实问题是否真实
2. 改文章（改完更新 `updated` 字段）
3. 推送
4. 回复感谢（可用 contact 身份）

```yaml
---
updated: 2026-11-05
---
```
